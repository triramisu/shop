# WEB-PAY-01 — Link VNPay và trạng thái thanh toán trên UI

## Hợp đồng tám phần (19/10/2026)

1. **Mục tiêu/phạm vi:** sau M5.7A local gate 537 test/image/prod smoke, ưu tiên nối storefront với API đã có để khách tiếp tục thanh toán đơn của mình. Phần SIT/IPN public của M5.7A vẫn chờ HTTPS, không gọi task trước hoàn hảo hoặc đóng M5. Không triển khai refund/query/scheduler, AWS, push hoặc CI/CD. Không thiết kế lại toàn bộ UI.
2. **Ownership/phụ thuộc:** source frontend ở `D:/shop-ui`, React18/TypeScript/TanStack Query5. Order/Payment API hiện hành là nguồn trạng thái; GET `/api/orders/{id}/payment` trả paymentAttemptId/providerCode/status/actionUrl. Không migration, không đổi backend hoặc secret. Query nằm dưới key `orders` theo user/order và dùng AbortSignal/client session guard.
3. **Luồng/bất biến:** trang chi tiết đơn đọc payment, hiển thị một CTA khi Order=PENDING, Payment=REQUIRES_ACTION, provider=VNPAY và URL hợp lệ. Mở handoff ở tab mới bằng native anchor để tránh popup bị chặn; giữ trang đơn để xem lại. Backend return hiện trả JSON, không tự đổi thành trang frontend trong task này. Chỉ Order API quyết định nhãn đã thanh toán; Payment SUCCEEDED nhưng Order còn PENDING phải hiển thị đang xác nhận, không tự chuyển PAID.
4. **An toàn/phi chức năng:** không đưa merchant secret vào React, không log/lưu action URL vào storage/analytics. Chỉ HTTPS/443, không userinfo/fragment, origin exact allowlist, path handoff VNPay cố định, attempt UUID trùng response, token đúng định dạng. Không cho redirect từ query/location.state/browser responseCode. Link tab mới noopener/noreferrer. Poll tối đa 12 request payment/60 giây mỗi đợt, không background hoặc retry lỗi auth/network; chỉ missing attempt 404/1407 được chờ. Hủy request/timer và xóa cache khi logout/đổi tài khoản; nút kiểm tra thủ công không tạo payment/order mới.
5. **Đầu ra:** DTO/API client, helper URL/view-state/poll policy, panel payment trong trang đơn, CSS scoped dùng token hiện hành; cấu hình origin công khai qua env mẫu, tests và README. Dùng skill ui-ux-pro-max theo concern component: Quick Reference, dữ liệu React/UX local và MASTER sẵn có, không cài Python hoặc thư viện mới. Giữ phong cách biên tập thoáng của Aydibro và hệ icon SVG hiện tại.
6. **Ca kiểm thử:** link đúng; JS/http/userinfo/evil subdomain/port/path/token/attempt mismatch bị chặn; status lạ/provider khác không có CTA; missing attempt/error/failed/expired/success-wait/paid/cancelled; budget hết/terminal/order đổi; session A trả muộn sau logout/B không rò cache; browser query giả thành công không quyết định state. Browser kiểm tra desktop/mobile/dark/reduced-motion với API fixture được ghi rõ là giả lập, không giao dịch thật.
7. **Nghiệm thu:** `npm run lint`, `npm test`, `npm run build`, `git diff --check` ở UI; browser smoke trong môi trường tách biệt, không chèn demo vào DB thật. Backend không đổi nên giữ bằng chứng full gate/image của M5.7A, không báo lại coverage backend như do UI cải thiện. Không đánh dấu sandbox E2E đạt từ mock API.
8. **Rollout/rollback:** biến `VITE_PAYMENT_ALLOWED_ORIGINS` chỉ chứa origin HTTPS backend public đã tin cậy (build-time, không phải secret). Dev fake vẫn dùng được, không yêu cầu Stripe/VNPay để build. Khi thiếu allowlist hoặc link bị backend chặn, hiển thị hướng dẫn an toàn thay vì mở tùy ý. Backend là nơi enforce expiry; API chưa cung cấp expiresAt nên UI không tự đoán countdown, không tự tạo attempt mới. Rollback bằng bundle UI trước đó, không sửa schema/trạng thái tiền. SIT, phối hợp expiry giữ hàng/reconciliation và go-live vẫn chưa hoàn tất.
